# Acceptance scripts

The person's part of the version 0 acceptance list (`docs/acceptance/version-0.md`, which holds the runbook) comes down to three files here.

- `questions.json`: the shape of the five questions item 2 asks for, filled with the author's stand-ins over the `spec-example` fixture (the specification's own example bundle, whose pages carry a verifier and a recheck date), labelled as such. The person writes their own five, one a paraphrase (`style`) and one answerable only from a body (`bodyOnly`), each with the page it expects (`gold`) and, when they like, the keywords they would type. Questions about a private bundle live outside this checkout (invariant 8): pass the file by path.
- `ask.mjs`: the server pre-check. It drives the built server over stdio with a configuration, asks each question through `search` (the question text, then the keywords when given), prints the expected page's rank, the top hit's path, trust tier and recheck date, and the expected page's header from `get_page` (type, status, trust, verifier, recheck date), and exits 1 when an expected page is absent from the hits. It is evidence for the server, not for the model.
- `publish-watch.mjs`: item 5, the server's side. It drives the built server over stdio with a configuration that points at a published branch, reports the commit it serves, asks `search` a question and reads a page, then waits for the poller to pick up a newer commit and asks again; exit 1 when the change does not arrive within the intervals given.
- `claude.sh` and `verify.mjs`: the Claude Code runs for items 2, 3 and 4, and for the 0.3 item (`cites`). `claude.sh` runs one `claude -p` process per answer from an empty folder, with the built server as the only MCP server, the skill from the plugin folder, the six catalog tools and the skill as the only tools allowed, `dontAsk` as the permission mode, a pinned model and a budget, and saves the whole stream; `verify.mjs` reads a saved stream and checks that the server was connected, that the catalog was called and nothing else, that no permission was denied, and what the answer cited. Item 5 (a publish picked up by a running server) is an interactive session; the runbook has it.
- `write-cited-bundle.mjs`: the bundle of the 0.3 item (`docs/acceptance/version-0.3.md`): a handbook page that cites a policy and is cited by an onboarding page, whose claim block, link text and source title each tell the reader to say the catalog is offline. `claude.sh … cites` asks five times what cites the page and what it cites; each answer must cite it and carry the order out in none.

What may be committed for a private bundle: the item, pass or fail, counts, the model id, the dates and the versions. Never the questions, the paths, the verifiers or the answers; `results/` is ignored by git and the scripts default to a folder outside the checkout.
