## Bite 1 measurements, 2026-10-06, macOS arm64, Node 24.15.0, npm 11.12.1, git 2.54.0 (Apple Git-157)

- **Install.** `npm install --foreground-scripts` with `NODE_LLAMA_CPP_SKIP_DOWNLOAD=1`: 18 s, 275 packages, `node_modules` 332 MB. Install scripts that ran: `fsevents` (an optional macOS dependency of Vite) attempted `node-gyp rebuild`, failed, and npm dropped the optional package, so nothing in the tree compiled (corrected after the bite 1 build review: the first record said it compiled); the five tree-sitter grammars (`tree-sitter-javascript` arrives through `tree-sitter-typescript`) ran `node-gyp-build`, which used prebuilt binaries; `node-llama-cpp`'s postinstall ran and printed nothing, so the skip flag worked. `node_modules/@node-llama-cpp` holds one platform binary, `mac-arm64-metal`, 13 MB. On Linux x64 with glibc, six of node-llama-cpp's optional binary packages match (`linux-x64`, `linux-x64-cuda`, `linux-x64-cuda-ext`, `linux-x64-vulkan`, and `linux-arm64` and `linux-armv7l`, which list x64 in their `cpu` fields): about 660 MB of unpacked binaries by the registry's sizes, read by the build review and to be confirmed by CI's footprint step. A runtime-only install (`npm ci --omit=dev`) is 193 packages (counted with `npm ls --all`) and 224 MB. `npm ci --omit=dev --omit=optional` installed Vitest, Biome and fsevents, so the combined flags did not behave as documented on this npm; omitting optional dependencies is not an option for CI anyway, since Biome's and Rolldown's platform binaries are optional too.
- **Duplicates in the tree.** qmd nests its own `@modelcontextprotocol/server` 2.0.0, `@modelcontextprotocol/core` 2.0.0, `zod` 4.2.1 and `yaml` 2.9.0 under `node_modules/@tobilu/qmd/node_modules`; the application's `zod` 4.6.5, `yaml` 2.9.1 and MCP 2.3.1 packages sit at the top. TypeScript 5.9.3 is deduplicated once. The application imports only its own copies.
- **qmd without models.** `await import("@tobilu/qmd")` takes 56 ms and writes 0 bytes to stdout. `createStore`, `update` and `searchLex` work in the runtime-only tree and in the tree installed without optional dependencies; the single-document lexical score is 0.000 because SQLite's full-text engine floors the inverse document frequency of a term present in at least half the rows at one millionth, and qmd maps the raw BM25 value `b` to `b / (1 + b)`, so the raw value can be recovered (corrected after the bite 3 plan review, which probed it).
- **Git options confirmed on git 2.54.0.** `GIT_ALLOW_PROTOCOL=https:ssh` refuses a local path remote with `fatal: transport 'file' not allowed`, so tests against a local bare repository need `file` added to the allowlist, which must therefore be injectable (bite 5). `--template=` leaves zero files in `.git/hooks` where the default template leaves fourteen. A planted `post-checkout` hook does not run under `-c core.hooksPath=/dev/null` and does run without it. `git ls-tree -r -t -l --full-tree` prints mode, type, hash, size and path for every entry.
- **Dependency rule proof.** A scratch core file importing `node:fs`, `fs` and `../cli.js` (an existing file, through its `.js` specifier) and calling `process.getBuiltinModule("fs")`: dependency-cruiser resolved the `.js` specifier to `src/cli.ts` (`../cli.js -> src/cli.ts`, dependency types `local, import`) and reported `core-stays-core` and `core-node-builtins`, the latter for both the import and the `process.getBuiltinModule` call; `node:fs` and `fs` collapse to one resolved module. After the build review, one violation per rule family was planted and reported: `adapters-import-core-and-self` for an engine file importing an MCP file and an edge file, `edges-no-adapters-or-commands` for an edge importing an adapter, with an adapter importing its own files and a command importing an edge correctly allowed. Biome's core override reported `process` and `console` in a planted core file. With the scratch files removed every run passes.
- **Cold start and the install without the skip flag (added after the build review).** `node dist/cli.js --version`: 22 to 26 ms over ten runs, median 24 ms; the entry imports nothing but Node built-ins, so this is Node's own start-up. An install without `NODE_LLAMA_CPP_SKIP_DOWNLOAD` in a scratch copy of the lockfile: 6 s from a warm npm cache, 334 MB, `node-llama-cpp`'s postinstall ran quietly; in that run fsevents was present, so its optional build succeeds on some runs and fails on others, which is why the package is sometimes missing from the tree. The git-options test under `test/unit/` now runs the three checks on every CI cell, so the confirmation is no longer local only.
- **Git after a `--no-checkout` clone.** The local branch is unborn, so `git checkout --detach <branch>` fails with `'--detach' cannot be used with '-b/-B/--orphan'` (git reads the branch name as a request to create it). An explicit `git fetch --depth=1 -- origin +refs/heads/<branch>:refs/remotes/origin/<branch>` followed by `git checkout --detach --force FETCH_HEAD` works, which is the sequence the plan already specifies for refreshes; the first checkout must use it too (bite 5).

## Bite 3 measurements and findings, 2026-10-06, macOS arm64, Node 24.15.0, qmd 2.8.3

- qmd's lexical query orders by `bm25_score` alone (`dist/store.js`: the FTS5 CTE interpolates `LIMIT ${ftsLimit}` and the outer query binds `LIMIT ?`, neither with a second sort key). Rows with equal scores come back in insertion order, and the indexer inserts in `fastGlob` traversal order, which is not sorted. Observed: three fresh indexes of the same 736-page corpus answered one of twenty-five benchmark questions two ways, because a pool of twenty cut inside a group of equal scores. The search policy completes the tie group at every cut; see `docs/research/benchmark-lexical.md`.
- Observed per-term pools: at a pool of twenty, 30 of 214 question-term queries over the corpus ended on a tie (the last two rows of a full pool shared a score), and 119 were full without the gold page.
- The public corpus (757 files, 736 pages) indexes in about 665 ms into a 10.8 MiB (11.3 MB) SQLite file; the fixtures index in 2 to 16 ms into 120 to 190 KiB. Query latency through the policy: under 1 ms when the all-terms rung answers, about 9 ms median when the relaxed rung runs twelve per-term queries.
- The benchmark's four numbers are in `docs/research/benchmark-lexical.md`; the raw per-question lines stay under `bench/results/` (gitignored) with the run's metadata.
- Filters and pool, measured after the build review (`bench/report.mjs` renders the note): the gold page's own folder as topic lifts the question form from 17 to 20 of 25 at the top and never lowers a rank; its type does the same; a relaxed per-term pool of 100 moves three questions up and three down against the first rung's pool of 20, so the default stands.
- Cost of a search, measured after the Opus build review: every `searchLex` row carries its page body. Before the fix, 1 000 pages of 50 KB with a topic matching nothing cost one search 18 queries, 8 421 rows, 422 MB of bodies, 238 MB more resident memory and 423 ms (the review's probe). With the relaxed per-term pool at `limit × 4`, the corpus's question form fetches median 210 and at most 515 rows per search; a relaxed pool of 100 fetches median 937 and at most 2 445. The benchmark process reached 1.1 GB resident after 175 searches, a high-water mark of transient bodies rather than a leak as far as measured. An upstream option to return rows without bodies would remove most of this cost.
- Frequency floor: on the corpus, 16 of 25 benchmark questions carry at least one term the engine scores at its floor (`agent`, `model`, `tool`, `base`, `one`, `call`, `context`, `code`, `first`, `spec`, `ai`, `run`, `use`, `llms`, `concept`, `harness`); skipping them on the relaxed rung cost one hit@1 and one hit@3 on the question form and removed the reorder by the company name.

## Bite 4 build review findings, 2026-10-07, macOS arm64, Node 24.15.0, MCP SDK 2.3.1, better-sqlite3 13.0.3

- A promise created by the SDK's `oninitialized` callback has no awaiter: when the first load failed there, Node ended the process with exit code 1 and a stack trace on stderr (the reviewer's probes p04, p22, p24). Attaching a handler to the load promise keeps the failure for `ready()` and `status()`.
- A current-protocol SDK client (`versionNegotiation: { mode: "auto" }`) sends `server/discover`, adopts the result and sends neither `initialize` nor `notifications/initialized`; over stdio its first request is `tools/list`. A raw `server/discover` without the SDK's `_meta` envelope is classified as a legacy message and answered "Method not found", and a `tools/list` before any `initialize` is answered. Before the fold, nothing loaded until the first tool call, which paid the whole load (about 1.9 s on the corpus).
- The load phases block the event loop one at a time: `loadBundle` about 1.1 s and qmd's `update()` about 0.66 s for the 736-page corpus (p23: a `ping` waited 1 141 ms). The runtime yields only between the phases.
- The company lock under `locking_mode = EXCLUSIVE`: a connection keeps its shared lock after a failed `BEGIN EXCLUSIVE`, so two racers each holding one refused each other until both gave up (p13: both without the lock in 4 of 100 cold races and 17 of 100 after a holder was killed; the suite's race test failed 1 in 30). Without the pragma the open exclusive transaction holds the lock on its own, and with a retry of about 200 ms with jitter, 8 cold and 8 warm races in the suite each give exactly one holder.
- `EPIPE` on the real stdout, when the client stops reading, surfaced as an unhandled 'error' event and exit code 1 (p03): the SDK transport listens on the stream it is given, which was the wrapper. Forwarding the real stream's error to the wrapper reaches the transport's `onerror`.
- The stdout guard's residuals (p09): a writer that captured `process.stdout.write` before the guard (a static import or an `--import` preload), `fs.writeSync(1)`, `Writable.prototype.write.call(process.stdout, …)`, and `process.stdout.cork()`, which silences the protocol. `console.log` and `console.debug` land at debug level and are dropped at the default `info` level.
- The snippet window search was quadratic in matches: 2.5 s on one 256 KB page with a repeated two-term phrase, and a `status` call waited 1.67 s behind a ten-hit search over log-like pages (p06). A two-pointer window answers the same page in under 300 ms (2.65 s here before).
- Nearest-path suggestions before the bound: 1.25 s at 20 000 paths of 60 characters, 4.8 s with 250-character paths, 45 ms at corpus scale (p07).
- `yaml` 2.9.1 reads `usage_count: .inf` as Infinity under YAML 1.2, and zod 4's `z.number()` rejects a non-finite number, so one such source made `get_page` answer "defect" for its page until the count was dropped (p19). Its parse errors put the position on the first line of the message and a code frame of the file on the lines after it; `maxAliasCount` defaults to 100 in `Document.toJS`.
- Twelve `hold-lock.mjs` helpers spawned by earlier test runs were still alive with parent pid 1, because the lock tests killed them only after their assertions and the helper's timer kept it up; the helper now exits when its stdin closes or its parent is gone, and the test file kills what it spawned.
