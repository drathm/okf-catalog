# 0001. Founding decisions

Status: a living record while the project is in planning. Each row says what was chosen, what was rejected and why, and whether it is settled. Dates are when the maintainer ruled. Section references point to [../intent.md](../intent.md); research references point to [../research/](../research/).

| # | Decision | Chosen | Alternatives and why not | Status |
|---|---|---|---|---|
| D0 | What the product is | One thing: an MCP server that serves a company's OKF bundle to agents, on a developer's machine or hosted. It states what it needs from a bundle (the intake contract, intent §3) and ships recipes beside it for publishing, deploying and keeping current. Checks, scaffolding and intake are not product | An earlier draft's kit of seven commands covering validate, publish, deliver, fetch, serve and more: too broad; serving is the actual problem | Settled, 2026-10-06 |
| D1 | Name and licence | Name `okf-catalog`, chosen 2026-10-06 after a check found no competing project; the exact name is free on npm and GitHub (similar names exist: a dormant skill named `claude-okf`, some config file names). Site `okfcatalog.dev`, unregistered when checked the same day; `okfcatalog.com` is taken. GitHub Pages on the domain. Licence: Apache-2.0 recommended. It is the licence of the OKF specification, of Google's Knowledge Catalog, of superops okf and of the MCP SDK, which is moving from MIT to Apache-2.0 (`@modelcontextprotocol/server` 2.3.1, released 2026-10-05, is Apache-2.0); it carries an explicit patent grant; it sits fine on MIT dependencies such as qmd; with it, a NOTICE file and a contributor licence agreement (D56) rather than a DCO sign-off, because the agreement's sublicensing grant is what keeps a later move to the AGPL or to commercial terms for a hosted edition possible, and a DCO grants nothing of the kind. The one cost: code under it cannot be copied into an MIT project such as qmd without relicensing, which the maintainer can grant for his own code | MIT: shorter, no patent grant, what qmd uses, and the same for a hosting business (neither licence stops another host). Dual MIT and Apache-2.0: paperwork for no gain. AGPL now: open source, but would make companies hesitate to adopt the code internally; kept as the option the agreement preserves. Other names: `okf-library`, `okf-shelf`, `okf-stacks`; `okf-catalog.dev` with the hyphen | Settled, 2026-10-07: Apache-2.0 |
| D2 | Language, and how qmd is used | TypeScript, Node 22 or later; qmd used as a library through its SDK (`@tobilu/qmd`: `createStore`, `update`, `search`, `searchLex`, `get`, `getDocumentBody`), never as a child process; the `qmd` command is not a run-time dependency, and its shell hook is never used | Go: would re-implement or shell out to qmd. Shelling out to the CLI from TypeScript: a process per query, the CLI's own config and model downloads, no typed results | Settled, 2026-10-06 |
| D3 | Validation | Not the product. The server checks its contract on load. The publish recipe runs existing OKF checkers (okflint, okf-schema); a trial of okf-core and the okf-skills validator decides whether the recipe ever needs more | A validator of our own: re-owning what maintained tools already do | Settled, as a recipe |
| D4 | Publish target | A git branch named `published`, fetched by the server | Tags: do not move on pull. Registries: new credentials | Settled |
| D5 | Where the bundle lives at run time | Pulled by the server into its own cache; never inside a plugin | Inside the plugin: stale under harness update rules | Settled |
| D6 | Retrieval base and pin | qmd, npm release 2.8.3 (`facd35e`); filters from the manifest until a release ships the metadata filter; the collection-scope defect on that release worked around by over-fetching | Track main: filter now, churn forever. superops okf: see research/retrieval-engines.md | Open; the release is recommended |
| D7 | Modes | Lexical-only default everywhere; full mode opt-in. Reservation recorded: if full mode changes results dramatically, the default is wrong; so the lexical-versus-full measurement is a version 0 item, on one laptop, on the benchmark corpus and the acceptance questions, and the default is a one-line setting per company either way. Measured since: bite 6 (`docs/research/benchmark-modes.md`, 2026-10-07) found qmd's full mode noisier and two to three orders of magnitude slower than the ladder, short of D51's threshold; bite 7 (`docs/research/benchmark-rerank.md`, the same day) measured the ladder's own candidates re-ranked by the reranker alone: applied as qmd applies it (the score blended with the position), it never moves a first result and changes no gold rank on production's keyword input; by raw score, another ranker than qmd's, it gains two questions and loses two on that input and lifts the question form from 17 to 19 first hits while losing two; a pass takes four to five seconds against the ladder's milliseconds. Short of its pre-registered bar. The lexical default stands on both. The reservation stays open at the maintainer's instruction, for stronger models, other inputs and a bundle with someone else's questions | Full by default: 2.3 GB on every machine and every container | Settled with a reservation, 2026-10-06; the reservation measured twice and kept open, 2026-10-07 |
| D8 | First clients | Claude Code locally; claude.ai web in version 1; Codex and Grok Build next | | Settled |
| D9 | OKF 0.2 texts | The server reads both date forms (a date alone in the 15 August 2026 text, a datetime in the 21 August text); the contract lets a company pin one | | Proposed |
| D10 | What the server serves | Pages passing the company's status rule, default `stable` and `deprecated`; a development flag admits drafts and labels them, local mode only. Amended by D77: a status outside the three the specification names is kept as written, never rewritten to `draft` (D61), and admitted only when the company's rule lists it or under the development flag, labelled with its own word as a draft is | | Settled; one page of the first bundle to promote before the first real publish; the amendment by D77 proposed, 2026-10-07 |
| D11 | Fetched content | Never executed. Git pull, then qmd's library re-index; no shell hooks; a `.qmd` config inside a bundle is refused | | Settled |
| D12 | Remote authentication | The server is an OAuth resource server (RFC 9728 protected-resource metadata through the MCP SDK's `requireBearerAuth` and `mcpAuthMetadataRouter`), because OAuth is the one credential claude.ai, ChatGPT and grok.com all accept; a static bearer is also accepted for the local CLIs. The authorization server is not written by us (D12b) | A fixed bearer header: claude.ai beta only, ChatGPT never. An external proxy with no owner | Settled in shape; D12b open |
| D12b | Authorization server for cloud mode | Open: a hosted provider that speaks MCP's OAuth profile with dynamic client registration, or Google Workspace or GitHub if a platform accepts them; to be researched before the version 1 spike | Writing an authorization server ourselves | Open |
| D13 | One instance per company | Separate process, database, cache, credential, skill id | A multi-tenant server | Settled |
| D14 | Cloud targets for the recipe | Google Cloud Run first (a public service with application-level auth, since the web agents cannot present a Google identity token; one minimum instance; qmd's allowed-hosts setting configured), then a Hetzner VPS recipe as the non-Google equivalent | Fly.io, Render, Railway: same price band, documented as alternatives, not maintained as recipes | Proposed |
| D15 | How the cloud server gets the bundle | Baked into the image by CI on each publish, so the running server holds no GitHub credential | A read-only deploy key with a timer pull: works, but puts a credential in the container | Proposed |
| D16 | Keeping the server current | Locally, a timer pull in the server process, default ten minutes. In the cloud, a new deploy per publish, from CI | Webhooks: need an inbound endpoint and a secret | Proposed |
| D17 | Contribution to superops okf | Outside this project; a goodwill pull request if the maintainer wants | | Open |
| D18 | Google Docs intake, scaffold, multi-repository aggregation | Future ideas, listed, not scheduled | | Settled |
| D19 | Who shapes pages for the engine | The server, in a derived copy in its own cache: it writes the `qmd: metadata:` block and the title, description and tags lines itself, and `get_page` serves the original; companies publish plain OKF (intent §6). This is the value proposition: qmd done right for OKF | The publisher pre-shapes each page: couples every company's publish step to qmd's conventions | Settled, 2026-10-06 |
| D56 | Contributions | Every outside contribution is covered by the Contributor License Agreement in `CLA.md` (adapted from the Apache ICLA 2.2, with a grant to sublicense under any terms and an assignment clause), signed once by a comment on the first pull request and recorded by the CLA Assistant action in `.github/cla/signatures.json` on the `cla-signatures` branch; the text is to be reviewed by a lawyer before the first outside contribution is accepted | A DCO sign-off (no relicensing right); a copyright assignment (contributors dislike it; the sublicensing grant is enough) | Settled, 2026-10-07 |
| D57 | Ownership and publication | okf-catalog is a product of Bitfusion PR LLC (bitfusion.tech): the copyright notice, the package's `author`, the plugin manifest and the contributor agreement's licensee name the company; the repository stays at `github.com/drathm/okf-catalog` until the company's GitHub organisation exists (a transfer keeps redirects); the package is public on npm as `okf-catalog`, published with provenance from a tagged release after a first manual publish by the maintainer | A personal project; a scoped package name | Settled, 2026-10-07 |
| D58 | No lock file in the package | The package ships no `npm-shrinkwrap.json`. npm honours a shrinkwrap found inside an installed package and installs its whole tree nested under the package, neither filtered by `dev` nor by platform: 0.1.0 installed 336 nested packages and 3.1 GB, development tools and every platform's native binaries included; the same tarball without the file installs 204 packages and 227 MB. Reproducibility of the maintainer's own installs stays with `package-lock.json` and `npm ci`; the release test asserts the file's absence | A shrinkwrap pruned of development entries (the foreign platform packages would still be installed); bundling the dependencies | Settled, 2026-10-07 |
| D59 | The readiness ledger as tests (D-A) | Every sentence of #2's "Holds" list asserted by a named test (section 5), but row 24 (the specification's own statements) and row 32's "never executed" (an absence); the nineteen sentences no test asserted, wholly or in part, get fourteen new tests | The ledger as prose: a regression found by the next reader, not by CI | Proposed (bite a) |
| D60 | One resolver for a page name (D-B) | `resolvePageName` turns `/p.md`, `./p.md`, `p.md` or the concept id `p` (one leading `/` or `./` stripped once, as today) into an admitted page or a served reserved file, or an error: not found, with the three nearest served paths; ambiguous, with each candidate and a name that resolves to it alone (`foo.md` beside `foo.md.md`: ask `foo` or `foo.md.md`); unknown or refused bundle. It takes a list of `{ bundle, catalog, fatal? }` and an optional bundle id from the start; the two-name rule is one helper the path-field classifier reuses | A lookup per tool; silently preferring the `.md` path (#3 and #5 call it an error) | Proposed (bite a) |
| D61 | An unknown status kept | No rewrite to `draft`: the word kept trimmed, case kept (`statusRaw` untrimmed), served as written when admitted (D77), reported (`status-unknown`, `unknownStatuses`); a list or mapping reported likewise and counted unknown, its word its JSON text; known values read case-insensitively; every output schema takes a string | The rewrite (hides the producer's word; §5.4 defines none) | Proposed (bite a) |
| D62 | Contract fields and windows | `contract: { runtime?, parameters?, computation?, executor?: { resource?, receipt? }, attester?: { resource? } }` on the page and in `get_page`'s provenance, any type; `usageWindow`; each projected source's `effectiveWindow` (`{ from, to, inherited }`) from one function, the source's window else the page's; all survive the 8 000-character omission (`outputs.ts:274-278`) within D78's cap; malformed values degrade, never refuse; nothing runs | The raw frontmatter only (gone past 8 000 characters); copying the window onto stored sources (#5 forbids it) | Proposed (bite a) |
| D63 | The OKF 0.1 `# Citations` | The lists under a level-one `Citations` heading (case ignored), up to the next heading, read as `sources` only on a page with none of `generated`, `verified` and `sources`; a one-link item gives `resource` and `title`, any other its text as `resource`; reported `legacy-citations` | Any depth or any page without `sources` (a v0.2 subsection would become sources); gating on a root `okf_version` (most bundles declare none) | Proposed (bite a); departs from #3 |
| D64 | Search filters | #4 as written: `tag`, `status`, `min_trust`, `freshness`, applied after the engine returns, checked in the order unknown, type, topic, tag, status, trust, stale, a path counted once; unknown tag or status fails in the tool with the values in use; `filtersExhausted`; no token added to either rung | Tags as query tokens (moves BM25; #4) | Proposed (bite a) |
| D65 | The overdue default (D-C) | Both freshness arguments omitted: overdue pages are hits, flagged `overdue since`; `fresh` or `include_stale: false` leaves them out; #4's nine-row table; the two contradictions fail before `search` | Today's default (`tools.ts:219`): it hides pages §5.5 calls stale but never says to hide | Proposed (bite a); amends intent §6 and the `stale_after` row of `version-0.md` §2.5 |
| D66 | The rank guard (D-D) | No change of engine rank. Before any source change, each question's gold rank in the eleven lexical configurations is pinned in `bench/expected/lexical-ranks.json`; `node bench/run.mjs --expect` exits 6 on any change and prints a moved top five as a local tripwire, saying a tie cut at the 500 cap is not a product failure; `--write-expect` with `--bundle` refuses a path inside the checkout, as `--out` does. CI's fixture answers (`test/expected/ranks.json`) are pinned after R1; a change of admission re-pins them and names the answers that differ | Top fives as the contract (tied scores come in insertion order, and the cap cuts a tie group in engine order, `search.ts:108-133`); summary rows only (moves cancel) | Proposed (bite a); rewords D-D |
| D67 | Branches (D-F) | Section 6 | Keeping `version-0` as the line (its name is a version) | Proposed |
| D68 | Versions and aliases (D-G) | Section 6 | An `include_stale` error from 0.3.0 (breaks `ask.mjs` and three MCP tests); removal while schemas strip unknown keys (a silent drop) | Proposed; departs from #4 |
| D69 | The graph tools | `citations` and `provenance` as #5; edges classified once at load after admission and stored on the page (`pathEdges`); inbound mentions and derivations built with the catalog; nothing fetched, run or indexed | A graph store; classifying at query time (the catalog already holds every fact) | Proposed (bite b) |
| D70 | Path-field classification | #5's steps; a bare relative string that contains a slash and resolves to nothing from the page's folder is tried once from the bundle root (edge `fromRoot: true`, one `path-field-root-relative` per page), a single-segment name, `./x` and `../x` never; a page file the bundle holds but did not admit is `unserved`, and admitted candidates win, so a held draft never makes an edge `ambiguous` | #5's strict reading (no edge on the specification's own example); a retry for any bare name (`revenue` from `tables/orders.md` would bind to a root page); root first (contradicts §6.2's relative form) | Proposed (bite b); departs from #5 |
| D71 | The walk | Breadth-first in edge order; each concept entered once per call, at its least depth; a later branch reaching it records an edge to it, carrying the same source fields as an expanded edge (`author`, `usage_count`, `last_modified`, the window), and does not expand it, so entering once drops no citation's record; the graph test asserts those fields on that edge; a cycle is an edge to an ancestor on the branch, recorded, the branch stopped; at most 200 concepts entered, then `capped: true`, beside depth's per-branch `truncated` | #5's tree (two branches, two entries: exponential at depth 8); a cap on distinct concepts over that tree (never fires) | Proposed (bite b); departs from #5 |
| D77 | Admission of an unknown status | The allow-list stays: an unknown status is admitted only when `serve.admit` names it (trimmed, case ignored) or under `serve.dev`, labelled as a draft is; the default stays `stable` and `deprecated`; `serve.admit` and `pack --admit` take any word but `draft`, and `pack` writes what the rule admits | Admitting every unknown status (#3): `serve.admit` would stop bounding what is served, `pack` would publish withheld pages, `archived` would be served as current | Proposed (bite a); amends the Settled D10; departs from #3 |
| D78 | Caps on the typed fields | Each field rescued from the frontmatter (`contract`'s five, `usageWindow`, `timestamp`) is returned whole up to 2 000 serialised characters, past that replaced by `{ omitted: "the <field> is over 2000 characters and is not returned here" }`, the 8 000-character note's form, which the output schema takes; `get_page`'s lists come under the result budget in bite b (D82) | Uncapped (a second unbounded channel); one cap for the whole provenance (one long field hides the rest) | Proposed (bite a); departs from #3 |
| D79 | The OKF 0.1 `timestamp` | A top-level `timestamp` returned as written in its own provenance field when `generated` is absent, reported `legacy-timestamp`; no `generated` synthesized | Folding it into `generated.at` (#3): a generator without `by`, which §5.2 requires and the loader and the strict output schema reject | Proposed (bite a); departs from #3 |
| D80 | Strict input schemas | Every tool's input schema a `z.strictObject` from 0.2.0: an argument the tool does not take (`tags`, `minTrust`) fails before the handler with the SDK's own message (`validateToolInput`, `@modelcontextprotocol/server` 2.3.1, `dist/mcp-DIH4cS6P.mjs:1810-1815`); `include_stale` declared until 0.5.0 | `z.object`, which drops an undeclared key silently: a misnamed filter returns an unfiltered answer with no word | Proposed (bite a) |
| D81 | The corpus guard in CI | A job of `.github/workflows/ci.yml`, Ubuntu, Node 24, on every push: `npm ci`, `npm run build`, `sh bench/fetch-corpus.sh` (four public repositories at pinned commits), `node bench/run.mjs --expect bench/expected/lexical-ranks.json` (lexical, no model), so a qmd bump from Dependabot cannot pass unmeasured | The guard as a local step only (CI never runs the harness) | Proposed (bite a) |
| D82 | The result budget | `citations`, `provenance` and `get_page` hold the whole result, text and structured, within `RESULT_BUDGET` (40 000 characters, `outputs.ts:20`): rows are kept in their stated order (#5's list order; walk order; for `get_page`, `verified` then `sources`, its provenance taking at most half the budget and the body the rest) until the budget is spent; every cut list keeps its total (`get_page`: `verifiedTotal`, `sourcesTotal`), and the two tools say `truncated: true`; no continuation cursor: the caller narrows with `depth` or starts from a sub-page | A cursor (state across calls for a read-only lookup); per-list caps alone | Proposed (bite b); departs from #5 |
