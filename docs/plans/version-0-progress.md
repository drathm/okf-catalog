Rules decided for this bite, each flagged to the reviewer as a judgement call:

1. **Unparseable frontmatter** is a refusal with its own rule, `frontmatter-unparseable`, added to the `RefusalRule` union: it is distinct from "no frontmatter" and the message names the YAML error.
2. **Unknown `status` value** (not `draft`, `stable` or `deprecated`): treated as `draft` for admission, so it is not served by default, with a degradation naming the value. The specification's "absent means stable" applies only to an absent key.
3. **`stale_after` by form.** `YYYY-MM-DD` is the date form: `at` is the start of that UTC day and the page is overdue when `now >= at`. An ISO datetime with an explicit offset is the datetime form: overdue when `now >= at`. A datetime without an offset is read as UTC and reported. Anything else is unparseable: no `staleAfter`, never overdue, reported. A form other than the one `spec_text` expects is reported as a degradation and still judged by its own rule.
4. **`verified`**: a bare mapping becomes a one-entry list; an entry without `by` and `at` is dropped and reported; `trust` follows §5.3 on what remains.
5. **Replacement link on a deprecated page**: the first link in the body, in document order, that resolves to another page in the bundle. This replaces draft 2's "first non-empty body line", because the specification's own deprecated example opens with a heading and links in the next paragraph.
6. **Links** resolve against every `.md` page path in the bundle, admitted or not, so a link to a draft counts as resolved; whether the target is served is a separate question `get_page` answers.
7. **`generated`**: `by` is required inside it per the specification; an entry without `by` is dropped and reported; `at` is optional and kept raw beside its instant.
8. **Bundle-level refusals**: a missing manifest outside development mode, caps exceeded, and an engine configuration folder or file (`.qmd`) anywhere in the tree. Per-file refusals: no frontmatter, unparseable frontmatter, no type, hash mismatch, size mismatch, a file present on disk but absent from the manifest. A manifest entry whose file is missing on disk is reported, not refused. A bundle-level refusal sets `report.fatal`, which the commands treat as "do not serve".
9. **Attachments**: any non-`.md` file other than `manifest.json` is counted, never parsed; a `.md` file is a page unless its name is reserved.
10. **Degradations are reported for admitted pages only**; excluded pages are counted. Refusals are always reported.
11. **The report's `encodedFolders`** is filled by the command after the engine's path codec runs (bite 3); the core leaves it empty.

Tests first, one file per module under `test/unit/`, each test named after the behaviour it pins. The fixtures from bite 1 are read into memory with `readFixture`; variants that are easier to express inline (a tampered byte, a bare mapping, CRLF line endings, a BOM) are built in the test. The table in plan §2.5 is the checklist. Done when every row has a passing test, `loadBundle` runs on all three fixtures with the expected reports asserted field by field, `npm run check` is clean, and the dependency rule still passes.

Review before build: an independent review of this plan. Review after build: an independent review of `contract.ts`, `page.ts`, `reserved.ts` and `load.ts` against the specification text and intent §6.

### Plan, revised after review

The port and the composition:

```ts
interface DerivedDocument { path; title; description?; type; tags; metadata: Record<string, string | string[] | number>; body }
interface EngineHit { path: PagePath; score: number; bm25: number }
interface IndexResult { documents; indexed; updated; unchanged; removed; skipped; notIndexed: PagePath[]; encodedFolders: string[] }
interface Engine {
  index(docs: readonly DerivedDocument[]): Promise<IndexResult>;   // writes its own generation tree, flips the link, indexes, verifies the count
  lex(terms: readonly string[], limit: number): Promise<EngineHit[]>;
  status(): Promise<{ documents: number }>;
  close(): Promise<void>;
}
```

`src/engine/qmd-render.ts` (pure, no qmd import): `renderDocument(doc) → string` writes `# <title>`, the description, the type value, the tag values joined by spaces, a blank line and the body, with whitespace collapsed in the first four; `encodePath(path)` and `decodePath(path)` implement the codec. `src/engine/qmd.ts` owns the store, the generation folders under a directory it is given, the symlink flip, the count check and the `multiGet` diff.

`src/search/query.ts`: the tokenizer above; `normaliseQuestion(question) → { terms; dropped }`. `src/search/search.ts`: the algorithm. Run all content terms plus the topic's path segments plus the type value, as one query at pool `P = limit × 4`; filter by type, topic (`path.startsWith(topic + "/")`), status rule and staleness; while fewer than `limit` survive and the rung returned `P` rows, widen `P` fourfold up to 500. If still short, run one query per content term at the same `P`, fuse by summed BM25 with a one-percent floor, rank by terms matched then score, append after the all-terms hits without duplicates. Every hit carries its rung and raw BM25; the response carries `considered` (distinct engine hits examined), `filteredOut` per reason, `strategy`, `terms`, `dropped`, and `reason: "no-content-terms"` when the question had none.

`src/fs/walk.ts`: `walkBundle(root, caps) → { files; hidden; refusals; fatal? }` as F1 describes. `LoadOptions` gains `hiddenPaths` and `walkFatal`; the core counts hidden paths, refuses `.qmd` among them by path, treats hidden and refused paths as present for the manifest, and measures caps over the files that arrived. `src/commands/check.ts`: walk, load, render the report, exit codes 0, 1 and 2, `--json`.

Dropped from this bite: `fs/cache-dir.ts` and `fs/swap-tree.ts` (the adapter owns its generations; the cache layout and the per-company lock, D32, go to bite 4). Added: `engine/qmd-render.ts`, the no-yield pin test, the walker's special-file and hidden handling, the benchmark's run metadata.

### Plan

Scope: `src/config/company-config.ts` (edge: parse and discover the per-company configuration), `src/fs/cache-dir.ts` and `src/fs/company-lock.ts` (edges: the cache folder and the one-process-per-company lock, D23 and D32), `src/source/local.ts` (edge: a bundle folder on disk, walked on each load), `src/serve/runtime.ts` (the composition: generations, single-flight refresh, close), `src/mcp/tools.ts` and `src/mcp/server.ts` (adapter: the four tools and the server factory), `src/mcp/text.ts` (pure: the text block of every result), `src/search/snippet.ts` and `src/catalog/nearest.ts` (core: snippets and nearest-path suggestions), `src/log.ts` (edge: JSON lines on stderr), `src/commands/serve.ts` and the `serve` wiring in `src/cli.ts`, `plugin/claude-code/*`, tests. The composition, in one paragraph. `serve` finds the configuration (`--config`, then `OKF_CATALOG_CONFIG`, then `./okf-catalog.yaml`), parses it, resolves the cache root and the company folder, makes the folder with mode 0700 and refuses it when it is a symbolic link, owned by another user, or writable by group or others, then takes the company lock. With the lock held it works in the company folder; without it (another live process holds the lock) it works in a private folder named by its process id, removed at exit. It opens the source (in this bite only `source.local`, a folder on disk; a `source.repository` configuration exits 2 with "git sources arrive with the next bite; use source.local"), builds the first generation (walk → load → derive → `engine.index`), redirects `console.log` and `console.info` to stderr so no dependency can write into the protocol channel, and calls `serveStdio(factory)`. The factory registers the four tools against a `Runtime`; every handler reads `runtime.current()` once at the start of its call and works on that generation to the end, so a refresh between calls is invisible and a refresh during a call cannot mix two catalogs. `refresh()` is single-flight: concurrent callers share one promise; the generation reference is swapped right after `index()` resolves (D28); `close()` waits for a refresh in flight, closes the engine, removes a private folder, releases the lock. Nothing in this bite triggers a refresh except tests; the poller that calls it is bite 5.

### Plan, revised after review

The composition, in one paragraph. `cli.js` first checks `process.versions.node` (22.12 or later) and the platform (`win32` exits 2 with one sentence). `serve` then reserves stdout for the protocol before anything else runs (D36): its first statement replaces `process.stdout.write` with a stderr writer and turns every console method into a JSON log record, the engine is imported dynamically after that, and the transport gets its own stream on file descriptor 1. Every human sentence (usage, configuration, environment, the fatal report) goes to stderr. It installs the shutdown handlers (stdin's `end` and `close`, `SIGINT`, `SIGTERM`, `SIGHUP`, and a synchronous `process.on("exit")` that removes the private folder), finds and parses the configuration (`--config`, then `OKF_CATALOG_CONFIG`, then `./okf-catalog.yaml`; an empty variable or one still holding `${` is an error and never falls through), resolves the cache root and the company folder, and starts `serveStdio(factory, { transport, onerror })` at once; the factory only constructs an `McpServer` with `instructions` (the data-not-instructions rule and the citation rule) and registers the four tools against the `Runtime`. A missing or invalid configuration does not exit: the server runs in a refusing mode where every tool and `status` return the fix, such as `/plugin configure okf-catalog` (D42). Nothing is walked, locked or indexed for a connection that only probes: the first load starts when a connection completes `initialize` or a tool is called, whichever comes first (D38). The first load makes the company folder with mode 0700 and checks every folder it created (not a link, this uid, no group or other write), takes the company lock, an exclusive SQLite transaction on `<company>/lock.sqlite` that the operating system releases when the process dies (D40), or falls back to `<company>/private/<pid>/` after sweeping the private folders of dead processes, opens the source (this bite: `source.local` only; `source.repository` exits 2 before the handshake with "git sources arrive with the next bite"), builds the generation in phases that yield to the event loop between them (walk → load → derive → `engine.index`), and publishes it. qmd's `update()` is the one phase that does not yield (0.7 s for 736 pages; recorded). Tool calls await the first load and hold a shared lease on the generation they read, so a refresh waits for leases to drain, swaps catalog and index together, and releases; calls arriving during a swap wait for the new generation. A refresh has three outcomes: `swapped`, `fatal` (the previous generation stays) and `failed` (an exception; when it came after the engine's link flip, the runtime re-indexes the current generation before the next search); `status` carries the last attempt. A fatal first load does not exit: the server keeps answering, `status` carries the refusal, the other tools return `isError` naming the rule, and the log says so (D39). `shutdown()` is idempotent, waits for the first load, a refresh in flight and the leases, closes the engine, removes this process's private folder and closes the lock; it runs from the handlers above and never from a server instance's own close (the SDK closes a probe instance, and runs the factory twice on a connection that probes and then initialises). The build's first task is a channel probe: a stub server with one marker only in `content` and another only in `structuredContent`, run through the Claude Code version at hand, recorded in the facts note; the tools are designed so that each channel stands alone whatever it shows. Nothing in this bite triggers a refresh except tests; the poller is bite 5.

The source, in one paragraph. `GitSource` owns `<company>/source/`, a shallow clone of one branch with no tags, no submodules, no templates and no checkout, created under the 0700 company folder and marked with a file of its own (`.okf-catalog-source`) at clone time: a refresh that finds the marker missing removes the folder and clones afresh, since the checkout is a derived copy, and `checkout` and `clean` never run anywhere else (D47). Every git command runs with an explicit environment: `HOME`, `PATH`, `LANG`, `SSH_AUTH_SOCK`, `SSH_AGENT_PID`, `GIT_SSH` and `GIT_SSH_COMMAND` kept so the person's keys, agent and credential helpers keep working; every other `GIT_*` variable dropped; `GIT_TERMINAL_PROMPT=0`, `GIT_ALLOW_PROTOCOL=https:ssh`, `GIT_ATTR_NOSYSTEM=1`, `GIT_CEILING_DIRECTORIES=<cache root>`; when the person has set neither `GIT_SSH_COMMAND` nor `core.sshCommand`, `-c core.sshCommand=ssh -o BatchMode=yes` so a passphrase prompt cannot hang a stdio server; and on every command `-c core.hooksPath=/dev/null -c core.attributesFile=/dev/null -c core.fsmonitor=false -c core.symlinks=false -c core.autocrlf=false -c core.quotePath=true -c core.protectHFS=true -c core.protectNTFS=true -c submodule.recurse=false -c maintenance.auto=false -c gc.auto=0 -c filter.lfs.smudge= -c filter.lfs.process= -c filter.lfs.required=false`, the option list ended with `--` before the repository or any path, a timeout on every call (the fetch's `pull_interval` at most, the clone's longer), and output captured, never printed. A refresh is `fetch --depth=1 -- origin +refs/heads/<branch>:refs/remotes/origin/<branch>`, then `ls-tree -r -t -l -z --full-tree FETCH_HEAD` read before anything is checked out: a symbolic link (mode 120000) or a gitlink (160000), a blob over `caps.fileBytes`, a count or total over the caps, a path the manifest rule would refuse (control characters, `..`, a backslash, an absolute path) or two paths that collide by case or Unicode normalisation refuses the commit as a bundle-level refusal and keeps the previous checkout (D43); otherwise `checkout --detach --force -- FETCH_HEAD` and `clean -fdx` inside the marked folder, so a removed page leaves the disk, and the walker runs on the result as the second line. The commit of `FETCH_HEAD` is the generation's `commit` and goes into `status`; the manifest's commit, when the two differ, is reported as a degradation and not refused. A repository string beginning with `-` is passed after `--` and is otherwise unremarkable; `describe()` and every error replace a credential in the URL with `***`. An unreachable remote with a checkout in place keeps serving it and logs `refresh.failed`; without one, the first load fails and the server refuses with the sentence, naming the repository as configured.

The poller, in one paragraph. `createPoller({ runtime, source, intervalMs, log })` runs `source.changed()` every interval (a `ls-remote --heads -- origin <branch>` against the served commit, or the fetch itself when the remote does not answer `ls-remote` cheaply) and calls `runtime.refresh()` only when the remote commit differs from the served one; its timer is `unref()`'d and cleared by `shutdown()`, so it never keeps a server alive after stdin closed; it runs from its timer and never from inside a lease (bite 4 review R18); two ticks never overlap (a tick that finds a refresh in flight returns at once); a failing tick logs and waits for the next interval, with no backoff beyond the interval in version 0 (D44); the interval is the configuration's `pull_interval`, with the minimum the configuration already enforces. The local source gains the same `changed()` for symmetry, by the walked files' hashes, so development mode also picks up edits at the interval.

`pack`, in one paragraph. `okf-catalog pack --config <path> --from <source checkout> --out <folder> [--admit ...] [--dev]`: walks `--from` as the walker does, loads it with the configuration's admission and `integrity: "none"` (a source checkout has no manifest), refuses anything the loader refuses (exit 1 with the report on stderr and nothing written), refuses an `--out` inside `--from` or the reverse by the cache's overlap rule, copies every admitted page and every attachment the admitted pages' folders hold into `--out` (a fresh folder; an existing non-empty one is refused), writes `index.md` into every folder that lacks one from the same generator the loader uses, keeps a company-written `index.md` and `log.md` as they are, writes `manifest.json` covering every file in `--out` with sorted keys, the source commit when `--from` is a git checkout (`git rev-parse HEAD`, through the same hardened runner) and the pack time from the clock (so `OKF_CATALOG_NOW` makes it reproducible), and prints the report on stdout as `check` does (D45). Drafts leave the bundle unless `--dev`. A page that links to a page that was not admitted keeps its link and the report says so (`linksToUnserved`), as the loader already does.

The recipe, in one paragraph. `recipes/publish/publish.yml` (a GitHub Actions workflow the company copies into its source repository) and `recipes/publish/publish.sh` (the same steps for a shell): install the pinned checkers (`okflint`, `okf-schema`, through `uv`), run them on the source, run `okf-catalog pack`, run them again on the packed folder, commit the folder to the `published` branch as a fresh tree with the source commit in the message, and push; concurrency one at a time; the workflow's token has write access to that one branch and nothing else runs in that job; nothing from the pull request's text reaches a shell; no `pull_request_target`. The recipe is documentation plus two files (D46); it is tested by running `publish.sh` against a local bare repository in `publish-loop.test.ts`, with the checkers stubbed by a flag, since they are Python tools the suite does not install.

The deferred items, in one paragraph. The lock's `owner` (pid and start time, read from `owner.json` when the lock is held) travels through `prepare()` into the runtime's status and into `status` as `lockOwner: { pid, startedAt } | null`, beside `lock`, and the one-line summary says `lock private (held by pid N since …)`. `QmdEngine.open` catches a store it cannot open or query (`SQLITE_CORRUPT`, `SQLITE_NOTADB`, "file is not a database"), moves the file aside under a dated name, creates a fresh store, and reports it through `resetOnOpen`, which the serve command logs as `engine.reset` and threads into the generation so `status.engine.resetOnOpen` carries it (the bite 4 build left it null); the lock database is never removed or rebuilt by the server, since a holder may have it open (D48).

The runner, in one paragraph. `runGit(args, { binary, cwd, timeoutMs, allowProtocols, env })` spawns an absolute `binary` (the serve command resolves `git` on `PATH` once at start and reports "git not found" through the refusing mode; tests pass the stand-in; no `GIT_BINARY` variable is read) with an environment built from a written keep list and nothing else: `HOME`, `PATH`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`, `TMPDIR`, `XDG_CONFIG_HOME` (the person's own configuration location, kept on purpose), `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` (Linux credential helpers), `SSH_AUTH_SOCK`, `SSH_AGENT_PID`, `GIT_SSH`, `GIT_SSH_COMMAND`, `http_proxy`, `https_proxy`, `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, `SSL_CERT_FILE`, `SSL_CERT_DIR`, `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO`, `GIT_SSL_CAPATH`, each copied only when set, never `LD_*` or `DYLD_*`; plus `GIT_TERMINAL_PROMPT=0`, `GIT_ALLOW_PROTOCOL=<allowProtocols>` (`https:ssh` in production; tests add `file`), `GIT_ATTR_NOSYSTEM=1`, `GIT_CEILING_DIRECTORIES=<cache root>`. Every command carries `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c submodule.recurse=false -c maintenance.auto=false -c gc.auto=0 -c protocol.allow=never -c credential.interactive=false -c transfer.credentialsInUrl=die -c fetch.fsckObjects=true` (the variable then re-allows the listed protocols), is given `--git-dir` explicitly once the clone exists, ends its option list with `--` before the repository or any path, runs in its own process group under a fixed timeout per command (`ls-remote` 30 s, clone and fetch 5 min, listing and extraction 5 min) after which the group is killed and the outcome is `failed`, streams its output (a listing is parsed as it arrives and stops at one entry over `caps.files` with a `too-many-files` refusal; an extraction goes to disk), and reports `GitError { code, stderr }` with stderr escaped, cut at the log's value cap, and URL userinfo (`scheme://user:secret@host`) replaced by `***` (`git@host` is not a credential). When the person has set none of `GIT_SSH_COMMAND`, `GIT_SSH` and `core.sshCommand` (the last read with `git config --get core.sshCommand` inside the clone, under the same environment, so `include` and `includeIf` count), `-c core.sshCommand=ssh -o BatchMode=yes` is added so a passphrase prompt cannot hang a stdio server; a person's own `GIT_SSH_COMMAND` or `GIT_SSH` passes through untouched. OpenSSH can still prompt in a configuration that asks it to; the group kill on timeout is what ends that, and the log says so. The person's global and system configuration stay in force, so credential helpers keep working; an askpass-only helper does not, since `GIT_ASKPASS` is not kept, and that residual is recorded.

The source, in one paragraph. `GitSource` owns `<work>/source/` (the company folder for the lock holder, `private/<pid>/` for a second server, so two servers never share a source): `repo.git`, a bare shallow clone of one branch (`clone --bare --depth=1 --single-branch --branch=<branch> --no-tags --template= -- <repository> repo.git`; a missing or unreadable `repo.git`, one whose `state.json` names another repository or branch than the configuration, or one whose fetch fails on a stale `.lock` file left by a killed git, is removed and cloned afresh); `tree-<commit>/`, one extracted tree per commit; and `state.json` with the repository and branch as configured, the extracted commit, the served commit and the time of the last successful fetch (D47). The source folder is checked like the other cache folders: a symbolic link where it should be is refused. Git is transport only: the server never runs `checkout`, `clean` or anything that writes a working tree, so no attribute, filter, hook or line-ending rule of the repository or the person can act on the bytes. A load is: `fetch --depth=1 -- origin +refs/heads/<branch>:refs/remotes/origin/<branch>` (the `+` accepts a rewound or rebased branch; the ref name is fixed by the configuration's grammar), then the commit resolved once with `rev-parse --verify refs/remotes/origin/<branch>^{commit}` (never `FETCH_HEAD`, which a failed fetch truncates) and used for everything that follows; `ls-tree -r -t -l -z --full-tree <commit>`, parsed on NUL with the padded size and `-` for trees and commits; `validateTree(entries, caps, bundlePath)`, a pure function that refuses the commit (a bundle-level refusal that keeps the served generation and the previous tree folder, D43) for a symbolic link (mode 120000) or a gitlink (160000), a blob over `caps.fileBytes`, more entries than `caps.files` or more blob bytes than `caps.treeBytes`, a path that fails the manifest's path rule or carries a `.git` segment or one of its HFS and NTFS disguises, two paths that collide under the engine's key (NFC then lower case), a path segment over 255 bytes, a path not in Unicode normalisation form C, or a `bundle_path` that names no tree entry; then extraction, `cat-file --batch` fed the blob names, writing each raw blob (probed: `cat-file` applies no filter and keeps CRLF bytes) into `tree-<commit>/` under its validated path with mode 0600 and folders 0700, checking each header's size against the listing; then `state.json`; then the walker runs on `tree-<commit>/<bundle_path>` as the second line, its errors rewritten to name the repository and `bundle_path` as configured, with the commit as `published.commit`. When the fetched commit equals the last attempted one, nothing is listed or extracted. Older `tree-*` folders are removed after a successful swap, each after `lstat` says it is a directory and not a link and its name matches the pattern; a failed extraction removes its own partial folder. An unreachable remote with a tree in place serves that tree and logs `refresh.failed`; at first load with a served tree on disk from an earlier run, that tree is walked and served at once and the fetch runs on the poller's first tick, so an offline start answers from the cache and `status` says when it last fetched; with nothing on disk, the first load fails and the server refuses with the sentence, naming the repository as configured (D39, D42), and `refresh()`, and so every poller tick, retries that first load until it succeeds. When the loader refuses the fetched commit at first load and a previously served tree is on disk, that tree is served and the refusal is reported as the last attempt (D43). `describe()` and every error replace a credential in the URL with `***`. The configuration accepts `https://` and `ssh://` URLs without userinfo and the `user@host:path` form only, and a branch of letters, digits, `.`, `_`, `-` and `/` that does not start with `-` or `.`, has no `..`, `//` or `@{`, and does not end in `.lock` or `/` (D50); `bundle_path` is `.` or a path that passes the manifest's path rule with no dot-leading segment. The minimum git is 2.30, read from `git --version` at start; an older one, or none on `PATH`, puts the server in the refusing mode with one sentence.

The poller, in one paragraph. `createPoller({ runtime, source, intervalMs, log, clock })` runs one whole tick at a time on a chained timer: `source.changed()` (`ls-remote -- origin refs/heads/<branch>`, the exact ref, compared with the last attempted commit, so a refused commit is not fetched again every tick; no line means the branch is gone, logged once while the served tree stays; an error is a failed tick) and, when the remote moved or the first load has not succeeded, `runtime.refresh()`; the first tick comes one interval after the first load, or at once when a served tree came from disk; a tick that finds the previous operation still running returns at once; its timer is `unref()`'d; `stop()` clears the timer, kills a running git group and awaits the tick in flight, and is called by every shutdown path, stdin's included, before the runtime drains; the rejection `refresh()` gives after shutdown is caught; `tick()` is exposed for tests, so no test sleeps through an interval; every tick logs `poller.tick` with `outcome` (`unchanged`, `refreshed`, `failed`), `ms` and `error`, fields the allowlist names; `status.poller` carries `intervalMs`, `lastTick` and `lastOutcome`. It never runs inside a lease (bite 4 review R18) and backs off no further than its interval (D44).

`pack`, in one paragraph. `okf-catalog pack --config <path> --from <bundle folder> --out <folder> [--admit ...] [--commit <sha>]`: walks `--from` as the walker does, loads it with the configuration's admission and `integrity: "none"` (a source checkout has no manifest), refuses anything the loader refuses (exit 1 with the report on stderr and nothing written), refuses an `--out` inside `--from` or the reverse by the cache's overlap rule over real paths and an `--out` that exists and is not empty, copies every admitted page, every reserved file the walker returned (`index.md`, `log.md`) and every attachment it returned, anywhere, never a hidden file and never the input `manifest.json`, writes `index.md` into every folder that lacks one from the generator the loader uses, writes `manifest.json` exactly as the fixture tool did (`buildManifest`'s object in its key order, `JSON.stringify(manifest, null, 2)` and a newline; `published_at` as `YYYY-MM-DDTHH:mm:ssZ` from the clock, so `OKF_CATALOG_NOW` makes it reproducible; `commit` from `--commit`, which the recipe passes from its own checkout, else the zero commit, never a `rev-parse` of the folder, which inside a repository names that repository's head), writes every copied name in normalisation form C, and prints the report on stdout as `check` does (D45). Drafts leave the bundle; there is no `--dev`. One refused file blocks the publish, as `check` reports it, since the recipe runs `check` first and the publisher sees what to fix. A kept company `index.md` that lists a page not copied is a reported degradation, not a refusal, and a pack-produced bundle re-admits under `require-manifest` with at most the degradations its source carried. The fixture tool `test/tools/make-manifest.mjs` is deleted once `pack` reproduces its output.

The recipe, in one paragraph. `recipes/publish/publish.yml` and `recipes/publish/publish.sh` with a README: the workflow runs on `push` of the source branch the company names, never on `published`, in two jobs: `build`, with `contents: read` and `persist-credentials: false`, installs the pinned checkers (`okflint`, `okf-schema`, through `uv` with hashes) and `okf-catalog` from a pinned commit or tarball (never a bare package name: the npm name is unclaimed), runs the checkers on the bundle folder, runs `okf-catalog pack --commit` with the workflow's commit, runs them again on the packed folder and uploads the folder; `publish`, with `contents: write`, downloads it and runs git only, committing the folder as a commit whose parent is the current `published` tip, with the source commit in the message through an environment variable and no event text in any `run:`, and pushing without force, so a race is rejected and the next run follows; actions pinned to commits; `concurrency` of one without cancellation; no `pull_request_target`; the README documents the repository rule that lets the workflow push `published` only (D46). The shell recipe does the same in POSIX `sh` with Node 22.12 or later, system git and `uv` named as its assumptions, finds the CLI through `OKF_CATALOG_BIN`, and takes the commit from `git rev-parse HEAD` of the repository it runs in.
