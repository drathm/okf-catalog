# Version 0.2 acceptance

What 0.2.0 is judged by: the readiness fixes, the readiness ledger as tests, the search filters, strict input schemas and the rank guard of [../plans/version-0.2.md](../plans/version-0.2.md), section 3.1. "Automated" means a test in the suite proves it on every run, at UTC+14 and UTC−11; the one scripted item needs Claude Code and a person's reading, as the items of the version 0 runbook do. The version 0 runbook ([version-0.md](version-0.md)) is run against 0.1.3 as published or any later release, and its instruments are kept working through 0.4.0: `ask.mjs` and the soak ask for `freshness: "any"` from this release.

## The guards' results

The corpus pin `bench/expected/lexical-ranks.json` was taken on 2026-10-07 from `95b635a` with a clean tree, on darwin arm64 with Node 24.15.0 and qmd 2.8.3, before any file under `src/` changed: 275 answers (25 questions in 11 configurations). Its summary equals every row of [../research/benchmark-lexical.md](../research/benchmark-lexical.md). `node bench/run.mjs --expect bench/expected/lexical-ranks.json` then held every gold rank and every top five after R1, after the seven readiness fixes and after the filters. The CI job ran it on Linux (Ubuntu, x64, Node 24.21.0) at the pin's commit and held every gold rank and every top five: Linux reproduces the ranks pinned on macOS.

## The scripted item: the overdue default

With a configuration serving the `behaviours` fixture in development mode off (`company: behaviours`, `source.local` the fixture, `types: [Term, Note, Widget]`):

```sh
sh bench/acceptance/claude.sh --checkout . --config <that configuration> --results <a folder outside the checkout> question "What is zeta?" terms/zeta.md
```

`verify.mjs` checks that the server was connected and the plugin loaded, that only the catalog's tools were called, that nothing was denied, and that the answer names `terms/zeta.md` and a trust tier. That the answer says the page is overdue is the person's reading: `terms/zeta.md` was due for a recheck on 2000-01-31, and with no freshness argument `search` now returns it as a hit, flagged `overdue since 2000-01-31`.

The plan's open question on `tag`, a string or a list (JSON Schema `anyOf`), was settled the same day. Over stdio the server lists every tool with `additionalProperties: false` and `tag` as `anyOf` a string of at most 200 characters or a list of at most eight. One `claude -p` run through `claude.sh` (Claude Code 2.1.292, `claude-sonnet-5-5`, 0.10 USD by the stream's estimate) was asked to search for `glossary` with the tags `alpha` and `glossary`: it sent `{"question":"glossary","tag":["alpha","glossary"]}`, got `terms/alpha.md` as the only hit with the other glossary page counted as without the tag, and `verify.mjs` passed.

The two instruments that call `search` with no recheck argument still find their page under the new default, so no limit was raised (issue 4): a three-cycle soak (`node bench/soak.mjs --cycles 3`) found `metrics/revenue.md` in every cycle, and `publish-watch.mjs` over the item 5 fixture repository found `terms/proofing-window.md` first.

What may be committed for a private bundle is as in version 0: the item, pass or fail, counts, the model id, the dates and the versions; never the questions, the paths, the verifiers or the answers.
