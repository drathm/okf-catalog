# Changelog

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The version in `package.json` names the release. 0.1.0 was published on 2026-10-07, before the clean-account run of the acceptance list in `docs/acceptance/version-0.md`, by the maintainer's choice; what that run finds goes into a later patch release.

## [Unreleased]

The work of 0.2.0: the readiness fixes cut from issues 2 and 3, the readiness ledger as tests, the search filters of issue 4, strict input schemas and the rank guard (`docs/plans/version-0.2.md`, section 3.1; `docs/acceptance/version-0.2.md`); of 0.3.0: citations and provenance over one bundle (issue 5; section 3.2; `docs/acceptance/version-0.3.md`); and of 0.4.0: a network of bundles (issue 3; section 3.3; `docs/acceptance/version-0.4.md`), whose entries close the lists of Added, Changed and Deprecated below.

### Added

- `search` filters by `tag` (one tag, or a list of up to eight a page must carry all of, compared without regard to case and nothing looser), `status` (the status a page is served with), `min_trust` (that trust tier or a higher one) and `freshness` (`fresh` or `any`). They are applied after the index answers and never added to the keywords, so no engine rank moves. An unknown tag or status fails before the search with the values in use, each JSON-quoted as it is stored (neither trimmed nor collapsed), cut at 200 characters, at most 50 listed and then the total; an unknown type lists the types in use the same way, and an unknown topic, like an unknown folder in `catalog`, the folders. The result counts each removal under the first check it failed (`filteredOut` gains `tag`, `status` and `trust`), says when a restrictive filter met the pool's cap with the answer short while the index held more matches past it (`filtersExhausted`), and its header names each removal.
- `get_page` takes a page's concept id, its path without `.md`, as well as its path; a name that is one page's path and another page's concept id (`foo.md` beside `foo.md.md`) is an error naming both, each with a name that means it alone; in a chain of three such names the middle page has none, and the error says so.
- `get_page`'s provenance carries the contract fields of an attested computation (`runtime`, `parameters`, `computation`, `executor`, `attester`) on a page of any type, the page's `usage_window`, each source's `effectiveWindow` (its own window with its dates, or `{ inherited: true }` when it takes the page's, whose dates the page's `usageWindow` carries once), and an OKF 0.1 `timestamp`. These survive the frontmatter's 8 000-character omission, and each is held to 2 000 characters with a note of its own.
- The two OKF 0.1 fallbacks the specification allows (§13.1): on a page without `generated`, a top-level `timestamp` is kept as its own field (reported `legacy-timestamp`); on a page with none of `generated`, `verified` and `sources`, the lists under a level-one `# Citations` heading are read as its sources (reported `legacy-citations`), each item's text and link cut at 500 characters.
- `serve.admit`, `pack --admit` and `check --admit` take a status of the company's own, any word but `draft`, trimmed and never blank, so a company that wants its `archived` pages served lists `archived`.
- A word of the admission list that no page carries, other than the three known statuses, is named in the load report (`unmatchedAdmits`), in the output of `check` and `pack`, and in a `serve.admit` warning in the server's log at each load: a typo such as `depreciated` admits nothing, and says so.
- The rank guard: `bench/run.mjs --write-expect` and `--expect`, which pin and compare each question's gold rank in the eleven lexical configurations and exit 6 when one moves; the corpus pin `bench/expected/lexical-ranks.json`; a CI job that runs the comparison over the public corpus on Ubuntu on every push; and `test/integration/rank-guard.test.ts`, thirty answers over the `behaviours` fixture through the real engine.
- The readiness ledger of issue 2 as tests: fourteen new tests for the sentences of its "Holds" list that no test asserted.
- The benchmark harness measures the ladder re-ranked (`--modes rerank`): the production ladder's twenty candidates, in the question and the keyword form, scored by qmd's reranker as qmd scores them, reported by raw score and by qmd's position blend, with the keyword list twenty deep and the production-limit rows as controls; the report writes `docs/research/benchmark-rerank.md` with a pre-registered bar's verdict; `docs/research/benchmark-lexical.md` is written only by a lexical-only run. The vector index is built only for the modes that read it, and a model no mode asked for is pointed at a file that cannot exist.
- `citations`: what a page cites and what cites it, from what the bundle states; nothing is fetched. Six lists: the page's body links with their text and nearest heading (a link to a page that is not served says `unserved`); the body links that point at it, its own links to itself included; its footnoted claims, each joined to the sources whose id it matches without regard to case, the first 50 of them with their total, with the sentence that carries the reference (the smallest block holding it, cut at 500 characters with an ellipsis, never a footnote's definition) and each source's author, usage count, last change and usage window; the sources no footnote cites; the footnotes with no source; and the pages whose `resource` or sources name it. A footnote reference counts only when its definition exists, as GFM reads it, and a reference written inside a footnote's definition is no claim. Each list carries at most 50 rows with its total, a pointing or deriving page's row names its status, and `partial` says the body was only partly analysed.
- `provenance`: where a page's sources lead inside the bundle; nothing is fetched, opened or run. The page's `resource`, sources and contract fields (`computation`, `executor`, `attester`) are classified as a URL, a page, a reserved file, an attachment, a folder, a scope, ambiguous, unserved, or nothing in the bundle; a value with whitespace in it is a description, a scope on a source, never a path or a URL. A `resource` or source that names a page enters it and lists that page's sources in turn, breadth first, each page once at its least depth, a later reach, a second listing on one page and a cycle each recorded and not followed, to `depth` 0 to 8 (4 when omitted) and at most 200 pages entered (`capped`); a page the depth stops says `atDepthLimit`. Each page carries its status, trust tier and recheck date, each source its author, usage count, last change and usage window, and a page lists at most 50 sources with their total.
- The loader keeps each body link's text and nearest heading and each footnote reference's block and heading, the text, heading and block cut at 500 characters with an ellipsis, a hard line break read as a space; it classifies every admitted page's path fields once admission is known, and builds the inbound links and derivations with the catalog. A path field written from the bundle root without a leading slash, as the specification's own example writes all of them, is read from the root when the page's folder holds nothing by that name and the path, normalised, still holds a slash, and reported once per page (`path-field-root-relative`); a page file the bundle holds but does not serve is `unserved`.
- The `status` tool reports the admission list's words that match no page (`unmatchedAdmits`), as the load report does.
- The benchmark harness records `loadMs`, the time the load takes, beside the resident set after it.
- The acceptance scripts: `claude.sh` allows the six tools and gains the `cites` item; `write-cited-bundle.mjs` writes the bundle it reads.
- A network of bundles (issue 3): a `network:` file names an audience's bundles, each with an `id`, a `source` (a local folder or a published branch) and, if it likes, its own `serve.admit`, `serve.dev` (a local bundle's alone, which turns integrity off for that bundle only), `serve.pull_interval`, `caps`, `types` and `spec_text`; the top-level keys are the defaults, caps key by key, and `limit_default` is the network's. One process, one lock, one cache folder and one store serve every bundle: each bundle is loaded on its own, its pages one qmd collection named by its id, re-indexed alone on its refresh, and every score is on one scale because the collections share one table. Refused, each with a sentence naming the key: `company` beside `network`, an id used twice, the ids `vendor`, `dist` and `build`, a local bundle anywhere in the okf-catalog cache folder or holding the network's part of it, a local bundle inside another's folder or holding it, folders compared by their real paths (a link to a folder, or its name in another case where the file system ignores case, is that folder), two repository bundles of one repository and branch whose `bundle_path`s are the same or one inside the other (a repository compared by its host and its path, whatever its scheme or user), and a top-level `serve.dev`.
- Every search hit and `get_page` carries its `bundle` and `conceptId`, and `citations` and `provenance` their `bundle`. `get_page`, `citations`, `provenance`, `catalog` and `status` take an optional `bundle`, never a blank one: a name two bundles serve is an error naming each page with its bundle and the name to ask for with that bundle, a named bundle is the only one read, and a not-found error names the nearest paths with their bundles. The three tools that take a page's name also take the name a result line prints, `<bundle>:<path>`, the path in quotes when the line quotes it; a path that holds a colon is always printed quoted, so the two never meet. Equal score and trust order by path, then bundle id.
- Each bundle loads, fails and refreshes on its own. A bundle the loader refuses at the first load (with no tree on disk to fall back on), or whose first load throws while another loads (`load-failed`), is reported and its pages leave the index; a bundle whose part of the index cannot be brought in line with what it serves (a drop that fails, or a failed refresh whose re-alignment fails too) is refused alone (`index-broken`) until a later write of it succeeds; a failed refresh keeps the bundle's previous generation. Each bundle is served as its first load lands, and beyond one bundle the first answer waits at most twenty seconds for the others: a bundle still loading then is `loading`, and is served when its load lands. Git that cannot be prepared (not on PATH, older than 2.30) is each repository bundle's own `load-failed` when the network holds a local bundle. Such a bundle is named in each search's first line (`not searched`), refused by name, and shown in `status`; the model reads a fixed sentence, the log the engine's or the file system's words. A repository bundle is tried again at its next poll, a local bundle, which has no poller, at a restart. The tools answer from the bundles that serve and refuse only when none does, naming each bundle's reason; the network refuses as a whole only when it cannot be prepared (its cache folder, lock or store, or git when every bundle is a repository's) or every bundle's first load threw, and a network of one bundle refuses as version 0 did, though a refusal for its index now says so rather than ask for the configuration to be fixed. Refreshes are single-flight per bundle, and one poller per repository bundle runs at that bundle's interval and moves only for its own bundle's state.
- `status` returns the manifest's `publishedAt` and the root index's `okfVersion`, which the server parsed and no tool returned; the load report and `check --json` carry `publishedAt` too.
- `pack --bundle <id>`: which bundle of the configuration a pack is, required when the file lists more than one; pack publishes one bundle, never a network.
- The benchmark harness's `--split` measures a network over the four unfiltered configurations (`docs/research/benchmark-network.md`; recorded, not gated): each corpus folder indexed alone against the same folder in the network of the four, on the gold page's rank and score, which is the shift D-D accepts; and the corpus as one bundle against the same pages split into a collection per folder, a near no-op by construction. `verify.mjs --expect-bundle` checks that an answer cites the page as `<bundle>:<path>`, whole, and `claude.sh … question … <bundle>` passes it; `ask.mjs` reads a gold page written `<bundle>:<path>` as that bundle's page.

### Changed

- With `freshness` and `include_stale` both omitted, `search` includes pages past their recheck date, each flagged `overdue since` its date, where it used to leave them out; `freshness: "fresh"` or `include_stale: false` leaves them out, and the two contradictory pairs are refused. A caller that omitted the argument now sees overdue pages, flagged.
- A `status` other than `draft`, `stable` or `deprecated` is no longer rewritten to `draft`: the word is kept, trimmed, with its case, and reported, and the page is served only when `serve.admit` names that word, or in development mode, labelled with its own word. The three known statuses are read without regard to case, and every output schema takes any status. By default nothing new is served.
- `pack` refuses to write a bundle in which no page is admitted (exit 2) unless given `--allow-empty`, so the publish recipe, which never passes it, fails on a typo that empties the bundle instead of publishing a branch with no page.
- Every tool's input schema is strict: an argument a tool does not take, such as `tags` or `minTrust`, fails with the SDK's validation error instead of being dropped in silence.
- Text lines quote a status outside the three known values, a type the company did not declare, and any type or status, declared or not, that carries a comma, a bracket, a quotation mark, a backslash or a control character; the verifier, a recheck date and the page's resource are quoted whenever they carry such a character. Inside the quotes, backslashes and quotation marks are escaped, backslashes first, so no character of the value can add a fact to a citation's brackets or close the quote.
- A page's citation header names at most ten sources, each id and resource quoted as a status or type is and cut at 200 characters with an ellipsis, then how many more, so neither a long list of sources nor a long source can add facts to the header or crowd the body out of `get_page`'s result.
- A page `usage_window` that is not a mapping of `from` and `to`, and a contract field without the shape the specification gives it, are reported `field-ignored`.
- `get_page`, `citations` and `provenance` hold the whole result within 40 000 characters, measured in the text and in the structured output alike. Every value a page wrote is cut: a link's text, a heading and a claim's block at 500 characters when the page is loaded, any other value at 2 000 in the structured output, 500 in a row of text and 200 in a page header, each with an ellipsis. `citations` builds at most 50 claims and gives each list that has rows an equal share of the budget, a list's unused share passing to the next and what the last leaves going back to the lists cut before it, so no list starves another; a claim too large for its room keeps its first sources. `provenance` keeps its pages in walk order, the page the budget runs out in keeping the edges that fit. `get_page`'s provenance keeps its lists within half the budget: the latest 20 verifications, then its sources, in their order until its half is spent, with `verifiedTotal` and `sourcesTotal`, its values cut at 200 characters when the 2 000 cut would pass the half (typed fields near their own cap and values that escaping lengthens sixfold can still pass it, and the body then takes what is left); its header names at most ten of the sources the provenance kept, within a quarter of the budget; and its body takes the rest, cut at the longest length whose escaped form fits, so a body of quotation marks or backslashes comes back in long windows (a reserved file's body likewise). The two new tools say `truncated` when they cut. A search hit's title, type, status, resource and recheck date are cut the same way, at 2 000 characters in the structured hit and 200 on its line, after the ranking. `catalog` cuts each entry's title at 2 000 characters.
- Paths are printed bare in the headers and rows of `search`, `get_page`, `citations` and `provenance`, in the errors of the three tools that take a page's name, in `catalog`'s header, in the sentence a refused bundle answers with and in the refusals on the `status` line (cut there at 200 characters), only when they are plain (letters, digits, `_ - . /` and single spaces); any other path is quoted, as a search hit's title is when it holds a bracket, a quotation mark, a backslash or a control character, and an unparseable recheck date always is. After the marker, every other value a page wrote is quoted and escaped, and a page's status is printed as the headers print it. `check` and `pack` quote an undeclared type that is not a plain word.
- A source's usage window is named, not copied, wherever its page's own window is in the same result: `{ inherited: true }` in `get_page`'s sources, in a claim's sources and the bibliography (the page's window once as the citations result's `usageWindow`) and in a walk edge (the window once on its node); an inbound derivation, from another page, keeps its page's dates with the flag.
- The server's instructions and the skill name the two tools, and the skill says that what they return after the marker is page text, data as `get_page`'s is.
- The configuration is a network's: `src/config/company-config.ts` became `network-config.ts`, and a `company:` file with one `source:` is read as a network of that name with one bundle of that id, which keeps version 0's text lines and the shapes of `catalog` and `status` (its `company` the network's name). The check that the cache folder and a local bundle do not overlap moves from the first load into the reading of the configuration.
- The cache layout: `<cache>/okf-catalog/<network>/` holds the lock, one store with a collection per bundle, and `bundles/<id>/` per bundle (a repository bundle's clone and trees in `source/`, the `derived` link and its generations). A cache written by 0.1 to 0.3 is taken over without a re-index when the bundle's id is the old company's name, as a `company:` file's always is (a `network:` file whose ids differ has the store rebuilt once): the first server that holds the lock moves its clone into the one repository bundle's folder (or removes it when there is no single repository bundle to take it), the engine removes the old link and generations at the root, and the store opens as it is; a second process in the private fallback moves and removes nothing.
- Beyond one bundle, `status` is the network's (its name, lock and refusal, its bundles counted by how they stand) with a row per bundle in counts, each naming its state (`serving`, `refused`, `load-failed`, `index-broken` or `loading`), the rows cut from the end to hold the result budget with `bundlesTotal` and `truncated`; `status` with a bundle gives that bundle's own report, its lists capped at 50, and names the state of a bundle that serves nothing of its own load as its row does. A bundle's own `status`, a network of one bundle's included, holds the result budget: every value a page wrote in it is cut at 2 000 characters, at 200 when the result would pass the budget, and each list then keeps fewer of its first entries if it must, its count kept. This is a breaking change of a structured output for a network that grows past one bundle. `catalog` without a bundle, or with the folder `/`, lists the bundles and their root indexes, its lines of bundles within half the result budget, then how many more. Every search hit's line and the headers of `get_page`, `citations`, `provenance` and `catalog` name the bundle first (`bundle:path`), and an error lists at most 50 pages, bundles or refusals, then the total. A network of one bundle keeps every line as it was.
- The log names the network and its bundles at start (`serve.start` carries `network`, `form` and `bundles` where it carried `company`, `source` and `dev`), and every load, refresh, poller tick and admission warning names its bundle, as do `index.broken`, `index.mended` and `load.slow`; `load.failed`, `refresh.failed` and `index.broken` carry the engine's or the file system's words as `detail`.
- The server's instructions, the tools' descriptions and the skill say that a page's path in more than one bundle needs its bundle, that a name as a result line prints it is taken back, and that beyond one bundle a citation names the bundle with the path.

### Deprecated

- `include_stale`, now the alias of `freshness` (`true` is `any`, `false` is `fresh`). It is accepted through 0.4.x and leaves the schema in 0.5.0, when a caller that still sends it fails loudly.
- A `company:` file with one `source:`, now the alias of a one-bundle network. It is read through 0.4.x, logged as the alias when the server starts (`serve.alias`) and noted by `pack`, refused beside `network:`, and removed in 0.5.0 together with `include_stale`. Until then its company may still be `vendor`, `dist` or `build`, which a `network:` file refuses as bundle ids, and a second note at start and from `pack` says so.

### Fixed

- A source's `usage_count` that is not a number (a string, a list, a mapping) was dropped without a word; it is now reported `source-malformed`, as a non-finite number already was, and the source is kept. A source's own `usage_window` that is not a mapping of `from` and `to` was dropped the same way; it is now reported `source-malformed`, and that source takes no window, never the page's, since its producer framed its count otherwise.
- `topicExhausted` said the topic may hold more whenever the first rung's pool reached its cap with the answer short, even when the index had run out of matches under the cap; it now needs the index to hold more matches past the cap, as `filtersExhausted` does.

## [0.1.3] - 2026-10-07

### Fixed

- The publish recipe (`recipes/publish/publish.yml`, the file a company copies) installs the server from npm at the exact version it came from, on Node 24, the line the CLI requires; it used to name a placeholder git commit and Node 22, on which the installed CLI refuses to run. Its actions are pinned to their current releases, and the recipe's README no longer describes a shipped lock file.
- `pack.sh`'s second okflint pass, on the packed folder, crashed okflint 0.5.0 with a Python error because the manifest's root does not cover that folder; the integration test's stub checkers could not see it. The pass now runs on a copy of the manifest beside a copy of the pack at the manifest's first root path. Found by running the real checkers on the acceptance fixture bundle.

## [0.1.2] - 2026-10-07

### Changed

- The README carries the npm badge, the measured install size and how releases are published. This is the first version published by the release workflow itself, through npm's trusted publishing with a provenance statement; the code is that of 0.1.1.

## [0.1.1] - 2026-10-07

### Fixed

- The package no longer ships `npm-shrinkwrap.json`. npm honours a shrinkwrap found inside an installed package and installs its whole locked tree nested under the package, development tools and every platform's native binaries included: `npm install okf-catalog@0.1.0` put 336 packages and 3.1 GB under `node_modules/okf-catalog/node_modules`. Without the file the same install is 204 packages and 227 MB, hoisted and filtered by platform. Nothing else changes; 0.1.0 works, it is only large.

## [0.1.0] - 2026-10-07

Version 0: serve a company's Open Knowledge Format 0.2 bundle to Claude Code, locally. Needs Node 24 or later (the Active LTS line) on macOS or Linux.

### Added

- `okf-catalog serve`: a stdio MCP server over one company's bundle, lexical mode, with four read-only tools. `search` takes keywords and the type, topic, overdue and limit filters, and returns every hit with its path, trust tier, verifier, recheck date, source count and resource, in the text and in the structured output; `get_page` returns a page's header, a marker line and the body as data, with its provenance; `catalog` lists a folder from its index file or generates the listing; `status` reports the load, the lock, the poller, the fetched commit and every degradation and refusal.
- The intake contract: pages are read by the specification's field table (`type`, `title`, `description`, `tags`, `status`, `stale_after` in both 0.2 texts, `generated`, `verified`, `sources`, `resource`, links, reserved files), degrade and are reported rather than refused (specification §11), and only a page without frontmatter or a type, an unsafe or oversize file, a hash mismatch or a missing manifest is refused.
- `okf-catalog check`: the contract applied to a folder, with the report as text or JSON and an exit code.
- `okf-catalog pack`: the published bundle written from a checkout, with generated index files and a manifest.
- A company configuration file (`okf-catalog.yaml`): the company name, a local folder or a git repository with its branch and bundle path, the admission rule, the development flag, the pull interval, the caps, the declared types and the specification text.
- The cache folder per company with its ownership and mode checks, and one process per company through a lock, with a private fallback for a second process.
- The git source: a bare shallow clone used as transport only, every fetched tree listed and validated before anything is written, raw blobs extracted into the server's own folder, a hardened runner, and a poller that refreshes when the branch moves.
- The publish recipe: a GitHub Actions workflow and two shell scripts that run the OKF checkers, pack, run them again, and push parent-linked commits to the published branch.
- The Claude Code plugin folder with the skill, shipped inside the package; the plugin asks for no settings and runs the `okf-catalog` command from PATH in the project folder, where the server finds `okf-catalog.yaml`.
- The benchmark harness over four public OKF bundles, with the lexical-versus-full measurement behind the maintainer's model approval.

### Not in this version

HTTP transport and authorization, full mode as a product option, Codex and Grok Build plugins, Windows.
